# Vision Motion

**Интерактивный предварительный скрининг зрения, которым управляют жестами перед обычной веб-камерой.**

ADMIT HACKATHON 2026 · кейс «MOTION: Камера вместо джойстика».

> Видео с камеры обрабатывается локально в браузере и не отправляется на сервер.
> Vision Motion — это предварительный скрининг, **не медицинский диагноз**. При проблемах со зрением обратитесь к офтальмологу.

---

## 1. Идея

Пользователь открывает сайт, разрешает камеру и проходит 5 визуальных тестов. Клавиатура и мышь не нужны: на все вопросы он отвечает жестами руки.

```
Landing ─👍→ Камера ─👍→ Подготовка ─👍→ Тест 1 … Тест 5 ─→ Итог
            (в каждом тесте: 👈👉☝️👇 выбрать → ✊ подтвердить → результат → 👍 дальше)
```

Камера в реальном времени показывает:

- скелет руки (21 точка и связи между суставами);
- рамку вокруг руки;
- распознанный жест;
- кольцо удержания жеста;
- уверенность распознавания (confidence);
- FPS.

Если что-то не так, **Error Mode** говорит, *что именно* неправильно и *как это исправить*.

## 2. Как запустить

Нужен Node.js 20+ и современный Chrome, Edge или Safari.

```bash
npm install        # также копирует MediaPipe WASM в public/ и докачивает модели при необходимости
npm run dev        # http://localhost:5173
```

Production-сборка:

```bash
npm run build
npm run preview    # http://localhost:4173
```

Камера в браузере работает только на `localhost` или по `https://`. Для проверки с телефона откройте сайт по HTTPS: например, через `npx vite --host` за HTTPS-туннелем (ngrok или cloudflared) либо задеплойте `dist/` на любой статический хостинг с HTTPS.

## 4. Как работает камера

1. `vision/camera/camera.ts` вызывает `getUserMedia` (фронтальная камера, 640×480, до 30 fps) и переводит ошибки браузера в понятные коды: `PERMISSION_DENIED`, `NOT_FOUND`, `IN_USE`, `INSECURE_CONTEXT`, `UNSUPPORTED`, `STREAM_ENDED`.
2. `vision/VisionRuntime.ts` владеет потоком, моделями и циклом `requestAnimationFrame`. Инференс запускается только на новых видеокадрах (проверяется `video.currentTime`). Лицо проверяется на каждом 5-м кадре.
3. Слой трекинга рисуется прямо в `<canvas>` на каждом кадре, **без React**. React получает снимок состояния через `useSyncExternalStore` не чаще ~11 раз в секунду или сразу при значимом изменении: сменился жест, ошибка или число рук. Поэтому приложение не перерисовывает дерево компонентов на каждый кадр и остаётся отзывчивым на слабых ноутбуках.
4. Модель запускается на GPU (WebGL). Если это не удалось, автоматически используется CPU.

## 5. Жесты

| Жест | Действие |
|---|---|
| 👍 THUMBS UP | начать / продолжить / следующий тест |
| ✊ FIST | подтвердить выбранный ответ |
| 👈 LEFT | выбрать левый ответ / направление влево |
| 👉 RIGHT | выбрать правый ответ / направление вправо |
| ☝️ UP | направление вверх / верхний вариант |
| 👇 DOWN | направление вниз / нижний вариант |
| ✋ OPEN PALM | отменить выбор, повторить инструкцию, пройти скрининг ещё раз |

Ответ **никогда** не записывается по одному жесту. Сначала на экране появляется «👉 Вправо — покажите ✊ для подтверждения», и только после ✊ появляется «✓ Ответ принят». После подтверждения действует cooldown.

## 7. Gesture Engine

Код находится в `src/vision/gestureEngine/`. Это собственная rule-based логика поверх 21 точки MediaPipe; готовый GestureRecognizer не используется.

### 7.1. Геометрия (`geometry.ts`, `classifyHand.ts`)

- Точки переводятся в «пространство пользователя»: изображение зеркалится, чтобы 👉 совпадало с правой стороной экрана, и выравнивается по соотношению сторон.
- Для каждого пальца считаются:
  - **reach** — во сколько раз кончик дальше от запястья, чем средний сустав;
  - **straightness** — косинус между фалангами.

  Из них через `smoothstep` получается непрерывная оценка «вытянутости» от 0 до 1. Она устойчива к повороту руки.
- Для большого пальца отдельно считаются вытянутость, направление вверх и положение над костяшками.
- Правила:
  - **✋** — все пальцы вытянуты;
  - **указание** — вытянут только указательный, а направление берётся по вектору от основания пальца к кончику (MCP→TIP) с проверкой, что он близок к оси;
  - **👍** — пальцы согнуты, большой палец вытянут и направлен вверх;
  - **✊** — все пальцы согнуты.
- **Confidence** складывается из «запаса» по каждому правилу и оценки руки от MediaPipe.
- Для почти правильных поз классификатор возвращает подсказку: `DIRECTION_AMBIGUOUS`, `EXTRA_FINGERS`, `THUMB_NOT_UP`, `FIST_LOOSE`, `FINGER_FORESHORTENED`.

### 7.2. Время (`GestureEngine.ts`)

- **Сглаживание.** Голосование большинством в скользящем окне 320 мс: жест должен занимать не меньше 60% окна при сглаженной confidence ≥ 0.55.
- **Удержание.** Жест фиксируется после удержания: 450 мс для указания, 500 мс для ✊, 650 мс для 👍, 700 мс для ✋.
- **Latch.** Пока пользователь держит тот же жест, он не срабатывает повторно. Руку нужно «отпустить».
- **Cooldown.** После фиксации жеста 650 мс новые жесты не принимаются.
- **Выход.** Движок отдаёт снимок состояния:

  ```
  Gesture: THUMBS_UP · Confidence: 0.94 · Stable: true · Error: null
  Gesture: UNKNOWN   · Confidence: 0.41 · Error: HAND_TOO_FAR
  ```

  Плюс событие `onCommit(gesture)`.

Классификатор и движок покрыты тестами (`npm test`). Фикстуры — **реальные точки MediaPipe**, извлечённые из открытых тестовых фото MediaPipe (👍, ✊, ☝️, 👈, ✌️, ✋✋). Их повороты проверяют все четыре направления указания.

## 8. Как реализован Error Mode

Вместо «жест не распознан» движок на каждом кадре ищет конкретную проблему, выбирает самую важную и показывает её с защитой от мерцания. Проблема должна продержаться 350 мс, прежде чем появится, и остаётся на экране минимум 1.1 с. Когда жест распознан, баннер меняется на зелёный «✓ Отлично! Жест распознан».

| Ситуация | Как определяется | Что видит пользователь |
|---|---|---|
| **Камера не видит руку** | нет руки дольше 700 мс | «Я пока не вижу вашу руку. Покажите ладонь в камеру на уровне груди…» |
| **Рука вне кадра** | часть точек у края кадра (<1.2%); сторона определяется с учётом зеркала | «Рука частично выходит за левый край кадра. Сдвиньте руку немного вправо…» |
| **Слишком далеко / близко** | размер ладони < 11% (≈ дальше 1.2 м) или > 45% высоты кадра | «Поднесите руку ближе к камере» / «Отодвиньте руку немного назад» |
| **Низкая confidence** | оценка руки MediaPipe < 0.6 или confidence правила < 0.55 | «Я плохо различаю пальцы. Поверните ладонь к камере…» |
| **Слишком быстрое движение** | скорость запястья > 3.2 размера ладони в секунду | «Рука двигается слишком быстро. Держите руку неподвижно» |
| **Жест показан слишком быстро** | жест пропал, пройдя 25–99% времени удержания | «Жест показан слишком быстро. Задержите жест на секунду» |
| **Две руки** | в кадре больше одной руки | «Оставьте в кадре только одну руку» |
| **Неясная поза** | подсказки классификатора | «Направление по диагонали — покажите строго вверх, вниз, влево или вправо», «Оставьте вытянутым только указательный палец», «Направьте большой палец строго вверх», «Разведите пальцы и держите руку неподвижно» |
| **Лицо вне зоны** | FaceDetector: лица нет дольше 1.5 с | «Сядьте так, чтобы лицо полностью оказалось в кадре» |
| **Лицо слишком низко** | центр лица ниже 66% кадра | «Поднимите голову немного выше» |
| **Слишком близко к экрану** | ширина лица > 50% кадра | «Отодвиньтесь немного назад» |
| **Неподходящий жест** | state machine отклоняет жест в текущей фазе | «Сначала выберите ответ: 👈 … 👉 …. Затем подтвердите ✊» |

Ошибки камеры, например «Камера недоступна. Проверьте разрешения браузера и попробуйте снова», показываются прямо в панели камеры вместе с кнопкой «Разрешить камеру».

## 9. State machine

Код находится в `src/state/testMachine.ts`. Это чистый reducer с явными фазами, без россыпи boolean-флагов:

```
LANDING → CAMERA_SETUP → PREPARATION → TEST_INTRO → TEST_ACTIVE
TEST_ACTIVE → ANSWER_SELECTED → ANSWER_CONFIRMED → (TEST_ACTIVE | TEST_RESULT)
ANSWER_SELECTED —✋→ TEST_ACTIVE          (отмена; другой жест-направление меняет выбор)
TEST_RESULT —👍→ NEXT_TEST: TEST_INTRO следующего теста | FINAL_RESULT
FINAL_RESULT —✋→ PREPARATION             (новый скрининг)
```

- `routeGesture(state, gesture)` переводит подтверждённый жест в действие для текущей фазы. Если жест сейчас не подходит, возвращается конкретная подсказка.
- У каждого теста своё состояние: испытания, ответы, время показа. Есть период наблюдения (`trialReadyAt`), пока идёт который ответы не принимаются.
- Кнопки-подсказки (fallback для мыши и доступности) и dev-панель используют **тот же** `routeGesture`. Поэтому поведение одинаковое при любом способе ввода.
- Приложение не ломается, если пользователь убрал руку, сменил или повторил жест, долго ждал или потерял камеру. Всё это либо состояния движка, либо переходы, которые state machine просто игнорирует.

## 10. Ограничения медицинского скрининга

- Результат **не является медицинским диагнозом**. Приложение никогда не пишет «у вас …». Вместо этого оно использует формулировки «результат отличается от ожидаемого», «может потребоваться дополнительная проверка», «обратитесь к офтальмологу при жалобах или повторяющемся результате». Отсутствие диагностических формулировок проверяется автотестом.
- Размер символов зависит от экрана, а расстояние до него контролируется только приблизительно. Поэтому острота зрения выражается в уровнях теста, а не в клинических единицах.
- Цветовые тесты зависят от цветопередачи дисплея, ночного режима и фильтров. Карточки — собственная генерация по принципу псевдоизохроматических таблиц, а не таблицы Исихары.
- Проверка сеткой Амслера и радиальной фигурой основана на субъективных ответах.

## 11. Как протестировать локально

```bash
npm test          # 23 теста: классификатор на реальных точках MediaPipe, временной движок, state machine, отсутствие диагнозов
npm run typecheck
npm run build
```

- **С камерой:** `npm run dev`, откройте http://localhost:5173, разрешите камеру и покажите 👍.
- **DEV DEMO MODE (без камеры):** http://localhost:5173/?demo. Появится панель разработчика с кнопками жестов и горячими клавишами: ← → ↑ ↓ = указание, Enter или F = ✊, T или Space = 👍, P = ✋. Это инструмент для разработки, а не основной пользовательский режим.
- **Error Mode вручную:**
  - уберите руку;
  - выведите ладонь за край кадра;
  - поднесите руку вплотную или отойдите далеко;
  - покажите ✌️;
  - покажите 👍 на полсекунды;
  - выйдите лицом из кадра на экране подготовки.
- **E2E без человека.** Chrome умеет подставлять видеофайл вместо камеры: `--use-fake-device-for-media-stream --use-file-for-fake-video-capture=gestures.y4m`. Так проект проверялся целиком: видео с циклом реальных фото 👍 → 👈 → ✊ проходит весь скрининг от Landing до итогового экрана через настоящий MediaPipe.

## 13. Приватность

- Видео с камеры обрабатывается локально в браузере и не отправляется на сервер.
- Видео и кадры не сохраняются.
- В `localStorage` сохраняются только итоги тестов: ответы, количество правильных, время прохождения, статус завершения.

## 14. Доступность

- Крупная типографика и контраст не ниже уровня AA.
- Цвет не единственный носитель информации: везде есть текст и символы ✓ и ◆.
- `aria-live` для статусов, `aria-label` у визуальных тестов.
- Поддержка `prefers-reduced-motion`.
- Адаптивная раскладка. На телефоне камера сверху, тест ниже, фронтальная камера работает как вход.
- Кнопки-подсказки жестов работают как запасной вариант для мыши и клавиатуры. Основной сценарий полностью проходится жестами.
